#+title: dorg Development Guide

This file is the durable architecture and development ledger for DOrg.  It is
not a task tracker: current work and its evidence live in the project's issue
tracker, not here.  Keep this file for source-backed design facts, module/test
maps, contributor commands, and long-lived decisions that should survive
outside an issue.

* Emacs support scope

GNU Emacs 30.1 is the supported CI target.  Emacs 29 is unsupported and
unverified following the test-runner skip-handling failure documented in
[[file:README.org::*Emacs 29 compatibility][Emacs 29 compatibility]].  Excluding a version from CI is not evidence of
a runtime incompatibility.  The existing package metadata minimum is
retained; it does not certify compatibility with every permitted version.

* Architecture

DOrg stores Org-shaped documents in either plain Org buffers or Dolt-backed
relational storage.  A Dolt-backed Org buffer is a read-only projection: users
read, navigate, query, and refresh it like Org, but writes enter through the
typed command/mutation door.  This boundary is implemented by
[[file:dorg-api.el][dorg-api.el]], [[file:dorg-command.el][dorg-command.el]],
[[file:dorg-app.el][dorg-app.el]], [[file:dorg-mutate.el][dorg-mutate.el]],
[[file:dorg-mode.el][dorg-mode.el]], and the storage modules listed in
[[*Modules][Modules]].

** Layer Diagram

Layers are listed top-down; each layer calls downward only.

- Public surfaces ::
  - [[file:dorg-api.el][dorg-api.el]] — programmatic mutation/query command API
  - [[file:dorg-command.el][dorg-command.el]] — interactive query and
    one-property mutation commands
  - [[file:dorg-app.el][dorg-app.el]] — =bin/dorg= CLI and serve HTTP command
    tree
- Query and command facades ::
  - [[file:dorg-ql.el][dorg-ql.el]] — public select facade
  - =dorg-ql-*.el= — AST, evaluator, and the model/plain/Dolt adapters

- One mutation door :: a public DSL form or intent lowers to typed patch IR;
  [[file:dorg-mutate.el][dorg-mutate.el]] plans and simulates the candidate;

- Model and derived views ::

    LOGBOOK data
  - [[file:dorg-parse.el][dorg-parse.el]] — Org buffer to model
  - [[file:dorg-render.el][dorg-render.el]] — model/Dolt to Org text
  - [[file:dorg-projection.el][dorg-projection.el]] — materialized-view state
    and regions
- Storage adapters ::
  - [[file:dorg-backend.el][dorg-backend.el]] — backend descriptors
  - [[file:dorg-registry.el][dorg-registry.el]] — file/backend binding
  - [[file:dorg-repo.el][dorg-repo.el]] — repository and schema lifecycle
  - [[file:dorg-dolt.el][dorg-dolt.el]] — SQL, commit, transport entry points
  - [[file:dorg-sql-gen.el][dorg-sql-gen.el]] — SQL text generation from model
    operations
  - [[file:dorg-ext.el][dorg-ext.el]] — extension schema and derived-index
    participants
- Runtime ::
  - [[file:dorg-transport.el][dorg-transport.el]] — SQL transport policy
  - [[file:dorg-dolt-server.el][dorg-dolt-server.el]] — sql-server registry,
    claims, leases, scrub, discovery

** Write Path

1. A caller — ~dorg-api-execute~, ~dorg-set-property~, =dorg mutate=, or the
   HTTP mutate route — submits a public DSL form or mutation intent.
2. [[file:dorg-api.el][dorg-api.el]] reads and normalizes the request,
   protects identity fields, and lowers it to typed patch IR.
3. [[file:dorg-mutate.el][dorg-mutate.el]] resolves the source, validates the
   typed patches, plans source-generic effects, and simulates the candidate
   image.
4. The store gate and transaction open: ~dorg-mutate-call-with-store-gate~,
   the SQL session lease, and ~dorg-transaction-commit~ where administrative
   import needs an exact base.
5. Pre-commit validation runs HEAD/base checks, structural consistency,
   extension index candidate validation, and postimage expectations.
6. Commit and receipt: ~dorg-sql-batch~ / ~dorg-commit~, the mutation log and
   postimage payloads, and the response envelope.
7. Derived readers refresh: materialized projections at the exact token,
   extension read-cache invalidation, and warm session freshness on the next
   read.

Retired boundaries are not supported alternatives.  Whole-file
edit/parse/diff/three-way reconciliation, save-hook write-back, dirty-buffer
promotion, and reconciliation conflict production are removed.  The current
write contract is the typed mutation path documented in
[[file:docs/mutate.org][docs/mutate.org]].
Parallel expectation checking has been replaced by candidate/postimage
validation in the single write path.

** Consumer Boundary

A downstream application reaches typed mutation, query, materialization,
import, and server lifecycle exclusively through the public surface.
Supported calls:

- ~dorg-api-execute~
- ~dorg-command-run-query~
- ~dorg-ql-select~
- ~dorg-materialize~ / ~dorg-refresh-materialized-view~
- ~dorg-register-extension~ and documented extension callbacks

Forbidden above the door:

- raw SQL as an application write API
- byte-splicing Dolt-backed projections
- save-hook whole-file reconciliation
- private =dorg-*--= helpers as compatibility API

** Server And Transport Topology

- Interactive ~dorg-mode~ :: ~dorg-dolt-auto-server~ starts the
  [[file:dorg-dolt-server.el][dorg-dolt-server.el]] detached managed daemon,
  which publishes a claim file in the store; clients then speak strict
  =mysql.el= transport through [[file:dorg-transport.el][dorg-transport.el]].
- CLI / batch command :: attaches to a compatible visible managed server;
  otherwise it fails by default with an explicit start remedy.  Optional
  ~dorg-dolt-server-autostart~ starts the same detached daemon.
- One-shot SQL fallback :: internal recovery seam only; it sits outside
  DOrg's managed-server health and target-selection guarantees.
- Test/runtime isolation :: DOrg-owned scratch roots live under the test
  runtime with store-local claims and indexes; cleanup may remove only owned,
  exact, canonicalized paths.

#+begin_src mermaid
flowchart LR
  subgraph starts[Start paths]
    im[Interactive dorg-mode] --> auto[dorg-dolt-auto-server]
    cli[CLI / batch command] --> attach[attach to compatible visible managed server]
    attach -->|none visible| fail[fail with explicit start remedy]
    attach -->|dorg-dolt-server-autostart| auto
  end
  auto --> daemon[dorg-dolt-server.el<br>detached managed daemon]
  daemon --> claim[claim file in the store]

The authoritative lifecycle code is in
[[file:dorg-dolt-server.el][dorg-dolt-server.el]].  Transport policy is split
into [[file:dorg-transport.el][dorg-transport.el]] and the SQL/lease
implementation in [[file:dorg-dolt.el][dorg-dolt.el]] so callers do not select
an unmanaged path accidentally.

* Public Surfaces

- Programmatic writes: ~dorg-api-execute~ in [[file:dorg-api.el][dorg-api.el]].
- Programmatic reads: ~dorg-ql-select~ in [[file:dorg-ql.el][dorg-ql.el]] and
  ~dorg-command-run-query~ in [[file:dorg-command.el][dorg-command.el]].
- Interactive commands: ~dorg-query~, ~dorg-goto-id~, ~dorg-set-property~,
  ~dorg-materialize~, ~dorg-refresh-materialized-view~, ~dorg-doctor~, and
  ~dorg-history~ through [[file:dorg-mode.el][dorg-mode.el]] /
  [[file:dorg-command.el][dorg-command.el]].
- CLI commands: =query=, =id=, =property=, =tag=, =title=, =mutate=, =import=,
  =doctor=, =serve start|stop|status=, and
  =dolt list|status|start|stop|stop-all|compact|rebind= through
  [[file:dorg-app.el][dorg-app.el]].
- Administrative import: ~dorg-import-document~ in
  [[file:dorg-import.el][dorg-import.el]].
- Extension registration and derived indexes: ~dorg-register-extension~ and
  related documented accessors in [[file:dorg-ext.el][dorg-ext.el]] /
  [[file:dorg-ext-read.el][dorg-ext-read.el]].

Documentation map changes are guarded by:

#+begin_src sh
make test SELECT='^dorg-test-project-'
#+end_src

That selector is the repository's docs checker.  It verifies module/test maps,
API census rows, demoted-symbol exclusions, CLI external-Dolt-SQL wording, and
install-surface constraints without starting Dolt.

* Code Style

- Use =lexical-binding: t= in Emacs Lisp files.
- Prefix public symbols with ~dorg-~ and private implementation helpers with a
  double-hyphen namespace such as ~dorg-mutate--~.
- Keep public functions documented with docstrings.
- Prefer source-generic APIs at boundaries; storage-specific helpers stay below
  their adapter.
- Treat Dolt-backed Org buffers and =/dorg:= views as read-only projections.
  Add a typed command when a write workflow is missing.
- Keep generated artifacts generated.  In this tree,
  [[file:docs/generated/mutate-grammar.org][docs/generated/mutate-grammar.org]]
  is produced by =make mutate-grammar=.

* Adding A Module

1. Add the root module file and provide feature.
2. Add a direct or transitive require where the module belongs.
3. If the module defines structs or macros, update ~dorg--reload-priority~ in
   [[file:dorg.el][dorg.el]].
4. Add or update tests under =tests/= and require them from
   [[file:tests/dorg-tests-runner.el][tests/dorg-tests-runner.el]].
5. Update the [[*Modules][Modules]] and [[*Tests][Tests]] example blocks in this
   file.
6. Run the focused tests for the changed area and
   =make test SELECT='^dorg-test-project-'= when maps or public docs changed.

* History

** Machine-First Reset

The 2026-07-24 machine-first reset stopped treating whole-file three-way
write-back as the release path.  Subsequent landings removed reconciliation
modules and conflict-runtime support; the surviving architecture is
DB-as-truth storage plus read-only projections and typed mutation.

** Deep-DOrg Ratification

The August 2026 mutation and projection work made the single write door
executable: public requests lower to typed patch IR, the engine simulates a
candidate image, validates core and extension postconditions before commit, and
returns structured receipts.  [[file:docs/mutate.org][docs/mutate.org]],
[[file:docs/api.org][docs/api.org]], and
[[file:docs/backend-extension.org][docs/backend-extension.org]] are the public
details; this file records the system shape.
