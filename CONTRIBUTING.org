#+title: Contributing

Released tags and
[[file:CHANGELOG.org][CHANGELOG.org]] define shipped compatibility; unreleased
source revisions do not.  Dolt is authoritative for Dolt-backed sources.
Their buffers are read-only projections, and writes use the typed mutation
API.  Do not reintroduce whole-file save or three-way synchronization.

This page is the public contributor guide.  The
[[file:docs/api.org::*Module dependency map][module dependency map]] and its
per-module tables document the repository structure.

* Getting Started

1. Fork and clone the repository
2. Run ~make test~ for the representative checks; use ~make test-full~ for full certification
3. Create a feature branch (~feature/your-feature~ or ~fix/your-fix~)

* Development

** Running Tests

#+begin_src sh
make test                                  # Representative test suite
make test-full                             # Full test suite
make test SELECT="^dorg-test-parse"          # Run specific tests
make test SELECT="^dorg-test-project-"       # Check docs/module/test maps
make compile                               # Byte-compile
make lint                                  # Run static checks
make clean                                 # Clean artifacts
#+end_src

** Code Style

- Use ~lexical-binding: t~ in all files
- Prefix all symbols with ~dorg-~ (public) or ~dorg--~ (internal)
- Write docstrings for all public functions
- Follow standard Emacs Lisp conventions

** Adding a Module

Follow [[file:DEVELOPMENT.org::*Adding A Module][Adding A Module]] for the
source/test maps, test-runner registration and module reference.  That guide
is the canonical checklist; do not maintain a second list here.  Run focused
checks first, then the full suite and ~make lint~ for code changes.

** Commit Messages

- Use present tense ("Add feature" not "Added feature")
- Keep the first line under 72 characters
- Reference issues when applicable

* Submitting Changes

1. For code changes, ensure the full suite passes (~make test-full~)
2. For code changes, byte-compile cleanly (~make compile~)
3. Open a pull request with a clear description

Documentation-only changes use Org structure/link review, ~git diff --check~
and the relevant documentation guards.  They do not require the code full
suite.  Execute documented examples separately on disposable data and retain
the source revision and observed results.
